# mahjong-tile-reader

並んだ麻雀牌（手牌）の画像を、機械学習なしで `123m456p789s11z` の文字列に読み取るブラウザ用ライブラリ。依存なし・1ファイル。

## しくみ

0. 写真の傾きと遠近（上が狭い台形）を直す（v0.4）
1. 牌の表面（白っぽい部分）が並ぶ横帯を見つける（明るさのしきい値は列ごとに写真に合わせる。v0.4）
2. 牌のすき間と横幅から1枚ずつに切り分ける（枚数は自動で13か14、指定も可）
3. 1枚ごとに表面を16×20のマスに分け、各マスの「暗さ・赤み・緑み・青み」を特徴にする
4. 登録した基準牌と比べて一番近い牌を答える
5. 萬子と判定したら、上半分の黒い数字だけで比べ直す（2段判定）
6. 並行して「規則」でも読む（基準なし）。見比べと食い違ったら自信なしにする

基準登録時には、縮小した基準も自動で作るので、小さく写った牌にも合います。

### 色の測り方（v0.2）

v0.1 は画素ごとに彩度のしきい値で「赤・緑・青・黒」に振り分けていたため、JPEG や縮小で色が薄れた赤・緑の線が黒に化けていました（小さいJPEGの「中」で最大6割）。

v0.2 はしきい値を使いません。各画素で「表面の色からどれだけ光が減ったか」(dr, dg, db) を出し、

- 暗さ = (dr + dg + db) / 3
- 赤み = (dg + db) / 2 − dr（緑と青は減ったのに赤は減っていない分。黒インクでは 0）
- 緑み・青み も同様

をマスごとに足し合わせます。どれも足し算なので、ぼかし・縮小・JPEG（色を2×2画素でならす）で色が薄く広がっても、マスの合計はほとんど変わりません。表面の色は「明るい方40%の画素の色ごとの中央値」で測るので、照明の色かぶりや、表面ににじんだ色にも引っぱられません。

比べるときの重みは `createReader({ weights: [暗さ, 赤, 緑, 青] })` で変えられます。サンプル絵柄では赤・緑を重くしても結果は変わらなかったので、既定は全部 1 です。

### 写真への対応（v0.4）

v0.3 までは合成画像だけで試していて、写真らしくした画像（下の「精度」）では 77% まで落ちました。原因は2つでした。

**明るい机・影で切り分けが崩れる**: 「明るさ 0.6 以上・彩度 0.25 以下」を牌の表面としていたので、ベージュの机も表面に、影の中の牌は表面でなくなっていました。v0.4 は列ごとに「その列の白さ（明るい方 3%）」と「机の明るさ（上下のふちの明るい方）」を測り、その間の 4 割の所で切ります。影や照明のむらは机も牌も同じように暗くするので打ち消され、明るい机も同じ列の牌より暗ければ表面になりません。差がほとんどない列（牌のない左右の余白）は表面にしません。どの列にも差がないとき（牌ぎりぎりで切り取ったとき）は v0.3 の固定のしきい値に戻します（`thresholds: { adaptive: false }` で常に固定にもできます）。

**傾き・遠近で枠がずれる**: 切り分けは横帯1本なので、傾くと端の牌が枠からはみ出し、遠近で上が狭くなると萬子の数字（上半分）がずれて読み違えていました。v0.4 は読む前に

- 並びの左端と右端の 2 割ずつで表面の高さの中心を比べ、ずれていれば回す（0.4° 未満は直さない）
- 帯の上の方と下の方で並びの横幅を比べ、違えば行ごとに横に伸ばして長方形に戻す（1% 未満は直さない）

をします（`rectifyImage()`）。直し方を間違えることもあるので、直した画像と元の画像の両方で読み、自信のある牌が多い方を採ります。そのぶん 1 手牌あたりの時間は約 2 倍（20ms 前後）になりました。`createReader({ rectify: false })` で止められます。

### 規則で読む力を上げた（v0.5）

自分の牌を登録しないと、規則で読める牌しか読めない。v0.4 では写真らしい画像で約半分しか読めず、四〜九萬と一索は 0% だった。v0.5 で規則を足して、登録なしでも約 84% を読めるようにした（誤りは約 1% のまま）。34種それぞれの決め手は [牌の特徴.md](牌の特徴.md) にまとめた。

- **四〜九萬**: 数字の形で読む。囲まれた白（四・五）、塊の数（六は点・横棒・脚に分かれる）、外枠の四隅の墨（七は左下が空く、八・九は右上が空く）、中ほどを横に通る墨の長さ（八は短く、九は乙の横画で長い）
- **一索**: 黒い墨がなく、緑の大きな絵に赤（頭）と青（尾）が混ざる鳥の絵
- **北**: 左右2つの塊がどちらも字の高さいっぱい、または右上の角が空く（東・南・西は上の横棒で右上まで墨が届く）
- **ふちの影を消す**: 表面のふちに触れる細い塊（すき間の影・隣の牌）を捨てる。白・一筒などが「黒い字がある」で読めなかった原因
- **濃いインクで数え直す**: 丸や棒がぼやけてくっついたら、しきい値を上げて数え直す（九筒・八索・七筒など）
- **数字は黒い墨**: 色みの残る暗い緑の丸（七筒）を萬子の数字と取り違えない

### 規則で読む（v0.3）

基準を登録しなくても、牌の決まりごとから読める牌があります。どれか1つでも合わなければ「決められない」として見比べに任せます。

**筒子・索子**: 色の粒を数え、形（丸い＝筒子、縦長＝索子）、並び方（粒全体の広がりを0〜1にして標準の配置と比べる）、赤い粒の位置（五の中央、六・七筒の下4つ、九筒の中段、七索の頂上、九索の中央列）、図柄の中心線に白線が引けるか（四・八は縦横とも引ける、二は横だけ、など）を確かめる。八索は傾いた棒がつながった「∧」「∨」、一筒は「大きな丸で中心と外周の色が違う」で読む。

**一〜三萬**: 上半分が「横線だけ」でできていれば本数で決める（線の太さがそろっていること、横線の外に薄いインクもないこと）。

**字牌（白の配置）**: 明朝体4種の太さ × 3段階の距離で調べた、遠目でも残る特徴を使う。

| 字 | 決め手 |
|---|---|
| 北 | 中心に縦の白線が通り、字が左右に分かれる（12/12） |
| 西 | 下段の中央が白く両端が黒い、または上の中央に穴。上が平ら（12/12） |
| 南 | ど真ん中に穴。遠くて穴が見えなければ、左下の角まで埋まっている（四角い）（12/12） |
| 東 | 縦画のすぐ左右に穴が対になって並ぶ。遠ければ、左下の角が斜めに欠ける（菱形）（10/12） |
| 中 | 赤い字で、下段の両端が白く中央だけ黒い（9/12） |
| 發 | 緑だけの字（赤や青が混ざる一索の鳥は外れる）（12/12） |
| 白 | 何も描かれていない |

字かどうかは「表面の中央に1文字分の大きさで、横の白線が通らない」で見分ける（調べた字牌72通りで、横の白線はすべて0本。索子・筒子は段の間に通る）。ぼやけて北の白線が消えても中央は左右よりくぼむので、くぼみがあるときは東・南の決め手を使わない。

食い違ったときは `prefer` で決めます（既定 `'auto'`: 見比べの確からしさが 0.35 未満なら規則を採る）。基準を登録していなければ、規則で読めた牌だけ答え、残りは `null`（文字列では `?`）になります。

## 使い方

```js
import { createReader } from './mahjong-tile-reader.js';

const reader = createReader();

// 1. 同じ絵柄の牌を1列並べた画像で基準を登録（<img> / <canvas> / ImageData）
reader.addReferenceRow(refImage, '123456789m123456789p123456789s1234567z');
// 何回かに分けて登録してもよい
// reader.addReferenceRow(img2, '1234567z');

// 2. 手牌を読む
const r = reader.readHand(handImage);          // 枚数を指定するなら { count: 13 }
r.text;        // "123m456p789s11z..."
r.codes;       // ["1m","2m",...]
r.tiles;       // 1枚ごとの { code, confidence, candidates, box, faceBox }
r.uncertain;   // 自信のない牌の位置（confidence < 0.08）
r.image;       // 実際に読んだ画像（傾き・遠近を直したもの）。r.tiles[i].box はこの画像の上の位置

// 3. 基準は保存・再利用できる
const saved = JSON.stringify(reader.exportReferences());
reader.importReferences(saved);
```

その他: `parseCodes('123m')`, `formatCodes([...])`, `tileName('1z') // 東`, `locateHand(image)`（切り出しだけ）, `rectifyImage(image)`（傾き・遠近を直すだけ）, `extractFeatures(image, box)`。

## 前提と対象外

- 手牌が横一列に並び、手牌の部分だけ（または手牌が一番目立つ）画像であること。傾きは 15° 未満、遠近は上下の幅の差 25% 未満まで直す（試したのは 2°・8% まで）
- 牌の表面が白っぽいこと（表面色が濃い牌セットは `thresholds` の調整が必要）
- 赤ドラは通常の5として読む。花牌・副露・河・傾いた牌は対象外
- 基準は読みたい画像と同じ絵柄で登録すること（ゲームごとに必要）

## 精度

サンプル絵柄の手牌400組（高さ34〜130px、ぼかし・明るさ・色かぶり・ノイズ、半数はJPEG品質50〜90%）。基準はいつも絵柄A（明朝・太字）で登録し、絵柄B（明朝・極太、丸・棒・色・配置も変えたもの）を読ませて「違う絵柄」を試す。

| 条件 | 正解 | 誤り | 読めず |
|---|---|---|---|
| 同じ絵柄（組み合わせ・既定） | 99.85% | 0.15% | 0% |
| 暗い赤・暗い緑の絵柄 | 99.78% | 0.22% | 0% |
| 違う絵柄B・見比べだけ | 95.43% | 4.57% | 0% |
| 違う絵柄B・組み合わせ（既定） | 98.42% | 1.58%（うち8割に自信なし表示） | 0% |
| 規則だけ・基準なし（A / B） | 87.90% / 88.25% | 0.55% / 0.60% | 約11% |

写真らしくした手牌（v0.4。`photo=1`）: 机（暗い木・明るい木・ベージュ・緑の布・灰色）の上に置き、牌の影を落とし、遠近（上の幅が最大 8% 狭い）・傾き（±2°）・照明のむら（片側が最大 35% 暗い）・影の帯（半数、最大 40% 暗い）を加えたもの。アプリと同じく枚数は教えて読む（`count=known`）。

| 条件 | 正解 | 誤り | 自信なし表示 | 手牌まるごと |
|---|---|---|---|---|
| v0.3（補正なし・固定しきい値、枚数は自動） | 77.18% | 22.82% | 30% | 35.3% |
| 同じ絵柄（組み合わせ・既定） | 98.46% | 1.54% | 48% | 89.5% |
| 違う絵柄B（組み合わせ） | 95.98% | 4.02% | 63% | 73.5% |
| 規則だけ・基準なし（A / B） | 82.26% / 82.11% | 1.31% / 1.22% | — | 約16% 読めず |
| （v0.4）規則だけ・基準なし（A / B） | 52.62% / 46.16% | 0.89% / 0.72% | — | 約47% / 53% 読めず |

- 残る誤りは 2萬↔3萬、6萬↔8萬 など萬子の数字。誤りの 6 割前後にしか「自信なし」が付かないので、アプリでは読み取り結果を一度目で確かめてもらう
- 効果ごと（各200組）: 遠近だけ 95.9%→99.4%、傾きだけ 枚数の正解 91.5%→99.0%、照明・影・落ち影だけ 99.4%（補正なし→あり）
- **本物の牌の写真ではまだ試していない**（下の「本物の写真で試す」）

- 色の測り方: v0.1（しきい値）は暗い赤・緑の絵柄で 98.40%。v0.2 以降は「八筒→西」「發→南」のような取り違えがなくなった
- 違う絵柄で残る誤りは、規則で読めない 一索・四〜九萬 に集中（一索→北、七萬→九萬 など）。使う絵柄で基準を登録すれば解消する
- 1牌ずつの規則テスト（`test/rules.html`、34種×4条件×2絵柄）では誤り0
- 参考: 最初の案の3×3色判定は77%。1手牌あたり約11ms

再現: `python3 test/serve.py` を起動してから（キャッシュさせない静的サーバー。`python3 -m http.server 8765` だとライブラリを書き換えても古いものが使われることがある）

## 麻雀点数計算アプリへの組み込み（`app/`）

**使う**: https://hitugihane.github.io/mahjong-tile-reader/ （GitHub Pages。ログイン不要。AI は使わず、牌の読み取りも点数計算もすべて端末の中で行う。外に出る通信はフォントの読み込みだけ）

claude.ai の公開ページに置いた版だけは、Claude にログインした人の利用枠で、自信のない牌を AI に確かめる（下の手順 3）。同じファイルで、`window.claude` があるとき（claude.ai の中）だけ AI を使う。

「写真で計算」の流れ:

1. **撮る**: 「枠に合わせて撮る」でカメラのプレビューに枠を出し、手牌（和了牌を右端に置いた14枚。副露があれば手の中の牌だけ）を枠に合わせて撮る。枠の範囲だけを切り出して読む。プレビューが使えない画面（claude.ai の公開ページなど、カメラが許可されないとき）では「カメラアプリで撮る」（`capture="environment"`）か「写真を選ぶ」を使い、写真の上で並びの左端・右端を2回タップして切り取る（2点を結ぶ線が水平になるよう回してから切る）
2. **端末の中で読む**: 手牌リーダーで読む（枚数は「手牌＋和了牌」で指定）。画像は端末の外に出さない
3. **自信のない牌だけ AI に聞く**: 「自信なし」「読めず」の牌があるときだけ、切り取った画像と「何枚目が不確かか」を1回で送る。AI が答えるのは聞いた位置だけ。AI が使えない画面ではこの手順を飛ばす。AI の呼び出しはアプリの `AI` オブジェクト（`available()` と `checkTiles()`）の1か所にまとめてある。いまは claude.ai の公開ページの sample 機能（見る人の Claude 利用枠）を使う
4. **確かめて直す**: 読み取り結果を並べ、自信なし・読めずは黄色、AI が読んだ牌は青で表示。牌をタップすると牌パレットが出て選び直せる（「この牌で合っている」で確定）。左から手牌の枚数ぶんが手牌、残りの1枚が和了牌になる
5. **点数**: ロン/ツモ・風・リーチ・ドラなどを入れると、既存の `calcPhoto()` で点数を出す

**自分の牌を登録**（ページのいちばん下）: 萬子・筒子・索子・字牌を種類ごとに左から順に1列に並べて撮ると `addReferenceRow` で登録し、`exportReferences()` の結果を localStorage（`mj-refs-v1`、全種類で約 800KB）に保存する。登録しなくても、規則で読める牌（筒子・索子・一〜三萬・字牌の一部）は読む。

- `app/mahjong-tile-reader.js` はライブラリのコピー（`import('./mahjong-tile-reader.js')` で読み込む）。ライブラリを直したらコピーし直す
- 公開するときは、claude.ai の公開ページに `麻雀点数計算.html` と `mahjong-tile-reader.js` の2ファイルを置く。sample 機能は画像つき（`capabilities: {sample: {images: true}}`）
- 通しの確認: `test/app-ai.html` はアプリを sample 機能のにせもの（聞かれた位置に正解を返す）入りで開く。`?ai=0` で AI なし。コンソールから `await registerAll()` / `await runCase([...14枚], { tilt: 1, persp: 0.04 })`

### 本物の写真で試す

1. スマホで公開ページを開き、「自分の牌を登録」で萬子・筒子・索子・字牌を1列ずつ撮る（または「写真を選ぶ」→左端・右端をタップ）。切り分けの枠（緑）が牌1枚ずつに合っているか見る。「○枚のはずが△枚に見えます」と出たら撮り直す
2. 手牌を14枚並べて（和了牌は右端）撮る。読み取り結果のうち、黄色・青の牌と、色の付いていない牌も全部、目で合っているか確かめる
3. 結果を記録する: 写真の条件（机の色・明るさ・斜めから撮ったか・距離）、14枚のうち正しかった枚数、色が付いた枚数、色なしで間違っていた枚数、AI に聞いたか、AI の答えは合っていたか
4. 10手牌くらい試し、色なしで間違う牌が多ければ、間違えた手牌の写真（切り取ったもの）を `test/` に置いて Claude に渡す（調べて規則やしきい値を直す）
5. 机が白い、牌の表面が黄ばんでいる・濃い色の牌セットなど、うまくいかない条件があれば書き残す
